# 貪心 (Greedy) 刷題全攻略：心法 + Paradigms + Techniques

> Greedy 是 DP 的「特例」——當每一步的最優選擇不需要靠未來的資訊也能確定時，就不用把所有子狀態都記下來，直接選一次就好。這也是為什麼 greedy 通常比 DP 快很多，但**適用範圍窄，而且很容易誤判**。

---

## Part 1：心法 — 什麼時候可以用貪心

Greedy 需要同時滿足：

1. **Greedy choice property（貪心選擇性質）**：每一步做「當下看起來最好」的選擇，不會因此失去達到全局最優解的機會。
2. **Optimal substructure**：跟 DP 一樣，大問題的最佳解由子問題的最佳解組成。

**最重要的心法：「感覺可以貪心」是陷阱，不是答案。** 每次想到一個貪心策略，**先花時間手動舉反例攻擊它**，而不是急著寫 code。

### 怎麼判斷該用 Greedy 還是 DP

問自己一個問題：**這一步的最佳選擇，會不會被「未來還沒發生的事」影響？**

- 不會 → 可能可以貪心（例如：活動選擇問題，選結束時間最早的，不會因為後面還有什麼活動而改變這步的最優性）
- 會 → 通常要 DP（例如：0/1 背包，這一步選不選這個物品，取決於後面還有哪些物品可以搭配，所以不能貪心地選「當下 CP 值最高」的）

## Part 2：怎麼證明貪心策略是對的

光是「感覺對」不夠，正式比赛/嚴謹寫法要能證明。常用兩種論證法：

### 交換論證法（Exchange Argument）— 最常用

假設存在一個最優解，它的排列方式**跟你的貪心策略不一樣**。證明：只要交換這個最優解裡相鄰的兩個元素，讓它變得更像貪心策略排的順序，答案**不會變差**（甚至更好）。重複這個交換過程，最終可以把任何最優解「搬」成貪心策略排出來的樣子，而不會讓答案變差 → 證明貪心策略至少跟最優解一樣好。

> 例子：活動選擇問題證明「依結束時間排序」是對的，就是典型的 exchange argument。

### Stays-ahead 論證

證明貪心解在**每一個步驟**，都不會比任何其他合法解差（例如：貪心解走到第 k 步時累積的某個指標，一定 ≥ 或 ≤ 任何其他解走到第 k 步的指標）。

### 反證法

假設最優解跟貪心解不同，推導出矛盾，說明貪心解必然是最優解之一。

## Part 3：常見 Greedy Patterns

### 排序後貪心（最常見的型態）

先用某個準則把資料排序，再依序處理。找排序準則的技巧：**從最極端的兩個元素想「誰應該先處理」，再推廣成一般規則**。

- **活動選擇 / Interval Scheduling**：依「結束時間」排序，每次選第一個不衝突的活動。
- **教室排課 / Interval Partitioning**：依「開始時間」排序，用 priority queue 追蹤目前有幾間教室在使用。
- **兩陣列配對使某個指標最優**：排序後依序配對（例如：任務排序讓總等待時間最小）。

### Priority Queue 貪心

每一步都從目前所有候選項裡，動態拿出「目前最優」的那個來處理。

- **Huffman coding**：每次合併目前權重最小的兩個節點。
- Dijkstra 本身也是一種「貪心 + priority queue」——每次都確定目前距離最短的未定點。

### 反悔貪心（Greedy with Regret）

用一個 heap 記錄過去做過的選擇，如果之後發現有更好的機會，就把之前的選擇「反悔換掉」。適合「一開始不知道最終最優解長怎樣，但可以隨時修正」的題目。

### Fractional vs 0/1

- Fractional（可以拿一部分）：通常可以貪心（分數背包：依單位價值排序，貪心拿）。
- 0/1（只能整個拿或不拿）：通常不能貪心，要改用 DP（0/1 背包）。**這是分辨「這題能不能貪心」的經典判斷點。**

## Part 4：Techniques

- **找排序準則**：想像只有兩個元素時，應該先處理哪一個？把這個「兩兩比較」的規則，寫成 `sort` 的 comparator，通常就是整體的貪心排序準則。
- **舉反例的習慣**：想到策略後，手造一個 3~5 個元素的小例子，自己跑一次策略，看看有沒有更好的解法策略沒找到。
- **貪心 + 資料結構**：貪心策略對了之後，常常需要搭配 priority queue、DSU（像 Kruskal）、單調隊列等資料結構才能有效率地實作出來。

---

## Part 5：解題 SOP

1. 想一個直覺的貪心策略（通常是某種排序準則，或每步選「當下最好」的選項）
2. **手動舉 2～3 個小反例，嘗試打破它**（這步不能省略）
3. 如果被打破 → 修正策略，或放棄貪心改用 DP
4. 如果撐過反例 → 用交換論證法或 stays-ahead 嘗試正式證明
5. 實作：通常是「排序 + 單純迴圈」，或「排序 + priority queue」

## Part 6：常見易混淆點

| 看起來像 | 但其實是 | 判斷關鍵 |
|---|---|---|
| 貪心 | DP（0/1 背包型） | 物品只能選一次，且選擇會影響未來能不能湊出答案 |
| 貪心 | DP（區間型） | 這一步的最優解，需要知道「未來子區間」的答案才能決定 |
| DP | 貪心 | 試著證明「不需要記錄歷史資訊，當下選擇就是全局最優」 |
